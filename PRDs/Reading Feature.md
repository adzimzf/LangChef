# Reading Feature

## Background

LangChef currently focuses on chat-based and flashcard-based learning. Users have no structured reading practice — a core pillar of language acquisition. Adding a reading feature allows users to consume level-appropriate texts, build reading stamina, and reinforce vocabulary they've already encountered in chat.

## Solution

### Overview

A new **Reading** mode where users select a difficulty level, receive a level-appropriate text (scraped from real news or LLM-generated), read it with vocabulary coloring and optional furigana (Japanese), then answer comprehension questions typed in the target language. The LLM validates each answer. Incorrect answers prompt a retry.

### Key Design Decisions

1. **Level-first flow** — User picks their level (JLPT N5–N1 for Japanese, A1–B2 for Indonesian) before fetching a text. Same level picker pattern as the Chat page.

2. **RSS news first, LLM fallback** — Fetch articles from public RSS feeds (NHK Web Easy RSS for Japanese, Detik RSS for Indonesian) rather than scraping HTML. RSS is intended for public consumption and avoids ToS concerns with raw HTML scraping. If the RSS fetch fails or the summary is too short for the requested level, fall back to LLM-generated text. The source is shown as a label.

3. **Level-appropriate length** — Text length follows CEFR/JLPT conventions:
   - N5/A1: 100–200 chars / 50–100 words
   - N4/A2: 200–400 chars / 100–200 words
   - N3/B1: 400–700 chars / 200–350 words
   - N2/B2: 700–1200 chars / 350–600 words
   - N1: 1200–2000 chars / 600–1000 words

4. **Furigana toggle (Japanese only)** — Text is annotated by the existing `annotate()` Rust function using Lindera. Users can toggle ruby markup on/off. Default: on for N5–N3, off for N2–N1.

5. **Vocabulary coloring** — Words that exist in the user's `review_items` are colored by difficulty (same palette as WordsList). Unknown words are unstyled.

6. **Comprehension questions** — After reading, the user is presented with 3–5 multiple-step questions generated by the LLM about the text. Questions are asked one at a time. User types answers in the target language.

7. **Answer validation** — Each typed answer is sent to the LLM for evaluation (correct / partially correct / incorrect + explanation). Incorrect: user sees feedback and must retry. Partially correct: user can continue or retry. Correct: next question loads.

8. **No SRS integration in v1** — Reading sessions are tracked as activity (`db_record_activity('reading')`) but words are not automatically added to review_items from this flow.

### User Flow

```
/reading
  └─ Level picker (JLPT / CEFR)
       └─ Language auto-detected from last session (or picker if not set)
            └─ "Start Reading" → fetch/generate text
                 └─ Reading view
                      ├─ Text (colored vocab, optional furigana toggle)
                      ├─ Source badge (NHK Web Easy / Detik / AI Generated)
                      └─ "I'm ready" → Q&A flow
                           └─ Question 1
                                ├─ Correct → Question 2 → ... → Summary screen
                                └─ Incorrect → feedback → retry same question
```

### Backend Changes (Rust)

- New command: `fetch_reading_text(language, level)` — attempts RSS fetch, falls back to LLM generation. Returns `ReadingText { title, body, source, language, level }`.
- New commands: `db_save_reading_session`, `db_get_active_reading_session`, `db_update_reading_session` — persist the current article + Q&A progress to SQLite so navigating away and back restores the session.
- New table: `reading_sessions` — stores article body, questions JSON, answers JSON, phase, and current question index. One active session per language at a time.
- New command: `generate_reading_questions(text_body, language, level)` — calls LLM, returns `Vec<ReadingQuestion> { question, expected_answer_hint }`.
- New command: `evaluate_reading_answer(question, user_answer, text_body, language)` — LLM call. Returns `AnswerEvaluation { result: "correct"|"partial"|"incorrect", feedback: String }`.
- Furigana annotation reuses existing `annotate()` in `furigana.rs`.
- Activity tracking: call existing `db_record_activity('reading')` at session end.

### Frontend Changes (React/TypeScript)

- New route `/reading` → `src/pages/Reading.tsx`
- New components in `src/components/reading/`:
  - `LevelPicker.tsx` — reuse/adapt from Chat page level picker
  - `ReadingText.tsx` — renders annotated text with vocab coloring + furigana toggle
  - `QuestionCard.tsx` — shows question, text input, submit button, feedback area
  - `ReadingSummary.tsx` — end-of-session summary (questions answered, retries)
- Add **Reading** tab to bottom nav in `Layout.tsx`
- New type in `src/lib/types.ts`: `ReadingText`, `ReadingQuestion`, `AnswerEvaluation`

## Requirements

### Functional Requirements

#### FR1: Level Selection
- **FR1.1** User SHALL select a difficulty level before a text is loaded.
- **FR1.2** Level options SHALL match the active language: JLPT (N5–N1) for Japanese, CEFR (A1–B2) for Indonesian.
- **FR1.3** Last-used level SHALL be remembered via `localStorage`.

#### FR2: Text Delivery
- **FR2.1** App SHALL attempt to fetch an article from the public RSS feed for the selected language.
- **FR2.2** On any failure (network, parse, timeout >3s, summary too short), app SHALL fall back to LLM-generated text without surfacing a raw error to the user.
- **FR2.3** Text length SHALL comply with the level-appropriate ranges defined above.
- **FR2.4** A source badge ("NHK Web Easy", "Detik", "AI Generated", etc.) SHALL be displayed.

#### FR2b: Session Persistence
- **FR2b.1** The current article, questions, answers, and reading phase SHALL be persisted to SQLite after each state transition.
- **FR2b.2** When the user navigates back to /reading, an active (non-complete) session SHALL be automatically restored — no reload required.
- **FR2b.3** The restored session SHALL resume at the exact phase and question index where the user left off.
- **FR2b.4** User SHALL have a "Start Fresh" option to discard the saved session and begin a new one.

#### FR3: Text Display
- **FR3.1** Words present in the user's `review_items` SHALL be colored by difficulty level.
- **FR3.2** For Japanese, text SHALL support a furigana toggle button.
- **FR3.3** Default furigana state SHALL be ON for N5–N3, OFF for N2–N1.
- **FR3.4** Furigana toggle state SHALL persist within the session (not globally stored).

#### FR4: Comprehension Questions
- **FR4.1** After reading, 3–5 questions SHALL be generated about the text.
- **FR4.2** Questions SHALL be presented one at a time.
- **FR4.3** User SHALL type answers in a free-text input in the target language.
- **FR4.4** User SHALL be able to view the original text while answering (collapsible or sidebar).

#### FR5: Answer Validation
- **FR5.1** Each answer SHALL be sent to the LLM for evaluation.
- **FR5.2** LLM SHALL return one of: correct, partially correct, incorrect — with a short explanation.
- **FR5.3** Correct answers SHALL advance to the next question.
- **FR5.4** Partially correct answers SHALL show feedback and allow user to retry or continue.
- **FR5.5** Incorrect answers SHALL show feedback and require the user to retry (no skip in v1).

#### FR6: Session Completion
- **FR6.1** After all questions are answered, a summary screen SHALL be shown (questions answered, retries taken).
- **FR6.2** Session SHALL be recorded via `db_record_activity('reading')`.
- **FR6.3** User SHALL be able to start a new reading session from the summary screen.

### Non-Functional Requirements

- **NFR1** Text fetch + question generation SHALL complete within 10 seconds (combined). Show a loading state.
- **NFR2** Answer evaluation SHALL complete within 5 seconds per question. Show inline loading on submit.
- **NFR3** Scraping SHALL have a 3-second timeout before falling back to LLM generation.
- **NFR4** Reading feature SHALL work for both Japanese and Indonesian.
